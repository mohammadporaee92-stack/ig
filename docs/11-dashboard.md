## ۳. ویزارد ۷ مرحله‌ای

`src/components/automation/wizard.tsx`

1. **نام** — نام + انتخاب حساب
2. **تریگر** — کامنت روی پست (تنها تریگر رسمی)؛ محدودهٔ همهٔ پست‌ها / پست‌های مشخص
3. **کلیدواژه‌ها** — چندتایی، کلیدواژهٔ منفی، حالت exact/contains، حساسیت به حروف، یک‌بار به ازای هر کاربر در هر پست
4. **Follow Gate** — روشن/خاموش، انتخاب checker، سیاست وضعیت نامشخص، سقف بررسی مجدد
5. **پیام‌ها** — چهار ویرایشگر (عمومی، خصوصی، Follow Gate، اصلی) با درج متغیر، شمارندهٔ بایت، Quick Replies و پیوست
6. **بازبینی** — خلاصهٔ کامل + فهرست خطاهای بازدارنده
7. **فعال‌سازی** — فعال‌سازی یا ذخیره به‌عنوان پیش‌نویس

پیش‌نمایش جریان (`flow-preview.tsx`) کنار ویزارد و به‌صورت زنده همان مسیری را نشان می‌دهد که موتور اجرا می‌کند — شامل گره‌های «انتظار برای لمس دکمه» و «پنجرهٔ ۲۴ ساعته».

## ۴. محدودیت‌های رسمی که در UI اعمال می‌شوند

این‌ها هم در کلاینت و هم دوباره در سرور (`src/server/automation-input.ts`) بررسی می‌شوند:

| محدودیت | مقدار | محل اعمال |
|---|---|---|
| طول متن پیام دایرکت | ۱۰۰۰ بایت | شمارندهٔ زنده + `validateMessageSizes` |
| تعداد Quick Reply | ۱۳ | Zod `.max(13)` |
| طول عنوان Quick Reply | ۲۰ کاراکتر | `maxLength` + Zod |
| پاسخ خصوصی | ۱ بار به ازای هر کامنت، تا ۷ روز | متن راهنما در ویرایشگر |
| پنجرهٔ پیام‌رسانی | ۲۴ ساعت | گره پیش‌نمایش + متن راهنما |
| رضایت کاربر | فقط با پیام/دکمه | هشدار صریح در مرحلهٔ ۴ و ۵ |

اگر پیام خصوصی هیچ Quick Reply نداشته باشد، ویزارد اجازهٔ فعال‌سازی نمی‌دهد — چون بدون آن «رضایت» هرگز ثبت نمی‌شود و جریان در `awaiting_user_interaction` گیر می‌کند.

## ۵. امنیت لایهٔ API

`src/app/api/_lib/handler.ts` — هر route محافظت‌شده از `withAuth` رد می‌شود:

- احراز هویت اجباری؛ بدون سشن ⇒ ۴۰۱
- برای mutationها هدر `x-requested-with: igflow` الزامی است (به‌علاوهٔ کوکی SameSite=Lax) ⇒ بدون آن ۴۰۳
- خطای Zod ⇒ ۴۲۲ با پیام فارسی؛ خطای پیش‌بینی‌نشده ⇒ ۵۰۰ **بدون** stack trace
- همهٔ کوئری‌ها `user_id` در `WHERE` دارند

نتایج واقعی بررسی‌شده روی HTTP:

```
POST   /api/automations                 201   ساخت موفق
PATCH  /api/automations/:id  enable     200   {"ok":true,"status":"active"}
PATCH  /api/automations/:id  duplicate  201   شناسهٔ جدید
DELETE /api/automations/:id  بدون هدر   403   درخواست نامعتبر (CSRF)
GET    /api/automations      بدون سشن   401   احراز هویت لازم است
POST   /api/automations      متن ۱۲۰۰B  422   محدودیت رسمی ۱۰۰۰ بایت
POST   /api/automations      ۱۴ دکمه    422   حداکثر ۱۳ دکمه
```

## ۶. نکتهٔ عملیاتی مهم — Singleton روی `globalThis`

در اولین اجرای واقعی، سرور پس از چند صفحه از حافظه خارج شد. علت: Next.js هر route segment را در باندل جداگانه‌ای ارزیابی می‌کند و hot-reload ماژول‌ها را دوباره اجرا می‌کند؛ در نتیجه به ازای هر مسیر یک نمونهٔ جدید PGlite/Pool ساخته می‌شد.

راه‌حل اعمال‌شده: نگه‌داری singleton روی `globalThis` در هر سه نقطه:

- `src/infra/db/client.ts` → `__igflowDb`
- `src/infra/queue/queue.ts` → `__igflowQueue`
- `src/server/container.ts` → `__igflowContainer`

این یک الگوی شناخته‌شده در Next.js است و برای اتصال به PostgreSQL واقعی هم لازم است (وگرنه connection pool نشت می‌کند).
