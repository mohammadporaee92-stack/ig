# استقرار رایگان: GitHub + Vercel + Supabase

هدف این راهنما یک چیز است: **کاربر شما روی «اتصال اینستاگرام» کلیک کند و وصل شود** — بدون تونل، بدون اینکه کامپیوتر شما روشن باشد، روی یک آدرس دائمی.

---

## چرا این ترکیب؟

| مشکل با تونل محلی | با استقرار |
|---|---|
| آدرس با هر ری‌استارت عوض می‌شود | دامنهٔ دائمی `igflow.vercel.app` |
| کامپیوتر شما باید روشن بماند | ۲۴/۷ بالاست |
| هر بار باید داشبورد متا را به‌روز کنید | یک‌بار تنظیم، تمام |
| فقط خودتان می‌توانید تست کنید | هر کاربری می‌تواند وصل شود |
| گواهی HTTPS موقت | HTTPS واقعی و معتبر |

هر سه سرویس پلن رایگان دارند و برای شروع کافی‌اند.

---

## ⚠️ مهم‌ترین نکته: مشکل Worker

**این را قبل از هر کاری بخوانید.**

معماری این پروژه یک **worker دائماً در حال اجرا** دارد (`npm run worker`) که صف رویدادها را پردازش می‌کند. Vercel سرورلس است — یعنی کد فقط وقتی درخواستی می‌رسد بیدار می‌شود و بعد می‌خوابد. **هیچ پروسهٔ دائمی‌ای وجود ندارد.**

اگر این مسئله حل نشود، اتفاقی که می‌افتد بی‌رحمانه است:

- وب‌هوک‌ها دریافت و در دیتابیس **ذخیره** می‌شوند ✅
- ولی **هرگز پردازش نمی‌شوند** ❌
- هیچ خطایی در هیچ لاگی نمی‌بینید
- فقط هیچ DMای ارسال نمی‌شود

**راه‌حل پیاده‌شده در این پروژه:** مسیر webhook با `after()` رویدادها را *بعد از* ارسال پاسخ ۲۰۰ به متا، در همان درخواست پردازش می‌کند. مهلت ۵ ثانیه‌ای متا نقض نمی‌شود و worker هم لازم نیست.

این رفتار روی Vercel **خودکار** فعال می‌شود و دو تست اختصاصی دارد (`tests/webhook.test.ts` → «حالت سرورلس»).

> **cron رایگان Vercel جایگزین این نیست:** پلن Hobby فقط **روزی یک بار** اجازهٔ اجرا می‌دهد. برای پاسخ فوری به کامنت بی‌فایده است — از آن فقط برای نگهداری روزانه استفاده می‌کنیم.

## مرحلهٔ ۱ — Supabase (دیتابیس)

PGlite فقط برای توسعهٔ محلی است. روی Vercel فایل‌سیستم موقتی است و با هر اجرا پاک می‌شود، پس به PostgreSQL واقعی نیاز داریم.

۱. در [supabase.com](https://supabase.com) پروژهٔ جدید بسازید (منطقه: نزدیک‌ترین به کاربرانتان)
۲. رمز دیتابیس را **جایی ذخیره کنید** — دیگر نشانتان نمی‌دهد
۳. به **Project Settings → Database → Connection string** بروید
۴. حالت **Transaction pooler** را انتخاب کنید

> 🚨 **حتماً از Connection Pooler روی پورت `6543` استفاده کنید، نه اتصال مستقیم `5432`.**
>
> هر تابع سرورلس یک اتصال جداگانه باز می‌کند. با چند درخواست هم‌زمان، سقف اتصال Postgres (روی پلن رایگان: ۶۰) پر می‌شود و خطای `remaining connection slots reserved for superuser` می‌گیرید. Pooler دقیقاً برای همین ساخته شده.
>
> کد پروژه هم روی سرورلس `max: 1` را اعمال می‌کند تا فشار اتصال کمینه بماند.

رشتهٔ اتصال شما چنین شکلی دارد:

<div dir="ltr">

```
postgresql://postgres.PROJECT_REF:PASSWORD@aws-0-REGION.pooler.supabase.com:6543/postgres
```

</div>

> ℹ️ نیازی به اجرای دستی migration نیست — پروژه هنگام اولین اتصال، schema را خودکار می‌سازد (`schema_migrations` آن را idempotent نگه می‌دارد).

> ⚠️ پروژه‌های رایگان Supabase پس از **یک هفته بی‌استفادگی** متوقف می‌شوند. برای استفادهٔ واقعی این را در نظر داشته باشید.

## مرحلهٔ ۳ — Vercel

۱. در [vercel.com](https://vercel.com) با GitHub وارد شوید
۲. **Add New → Project** ← مخزن `igflow` را import کنید
۳. Next.js خودکار تشخیص داده می‌شود — تنظیمات build را دست نزنید
۴. **قبل از Deploy**، در بخش Environment Variables این‌ها را وارد کنید:

| متغیر | مقدار |
|---|---|
| `DATABASE_URL` | رشتهٔ اتصال Supabase (پورت **6543**) |
| `AUTH_JWT_SECRET` | یک رشتهٔ تصادفی ≥۳۲ کاراکتر |
| `TOKEN_ENCRYPTION_KEY` | کلید **دقیقاً ۳۲ بایتی** |
| `IG_APP_ID` | Instagram App ID |
| `IG_APP_SECRET` | Instagram App Secret |
| `IG_WEBHOOK_VERIFY_TOKEN` | یک رشتهٔ تصادفی دلخواه |
| `CRON_SECRET` | یک رشتهٔ تصادفی دلخواه |
| `WEBHOOK_SIGNATURE_REQUIRED` | `true` |
| `AUTH_COOKIE_CROSS_SITE` | `false` |
| `NODE_ENV` | `production` |

ساخت کلیدها:

<div dir="ltr">

```bash
openssl rand -base64 48        # AUTH_JWT_SECRET
openssl rand -base64 24        # TOKEN_ENCRYPTION_KEY  (۳۲ بایت بعد از decode)
```

</div>

> 🚨 **`TOKEN_ENCRYPTION_KEY` را بعداً عوض نکنید.** تمام توکن‌های ذخیره‌شده با آن رمزنگاری شده‌اند؛ با تغییرش همهٔ اتصال‌ها باطل می‌شوند و کاربران باید دوباره وصل شوند.

۵. **Deploy** را بزنید.

آدرس دائمی شما آماده است: `https://igflow-xxxx.vercel.app`

۶. حالا دو متغیر باقی‌مانده را که به همین آدرس نیاز دارند اضافه کنید:

| متغیر | مقدار |
|---|---|
| `APP_URL` | `https://igflow-xxxx.vercel.app` |
| `IG_REDIRECT_URI` | `https://igflow-xxxx.vercel.app/api/instagram/callback` |

سپس **Redeploy** کنید (متغیرهای جدید فقط با build جدید اعمال می‌شوند).

## مرحلهٔ ۴ — به‌روزرسانی داشبورد متا

حالا آدرس‌ها را از تونل به دامنهٔ دائمی تغییر دهید.

**Instagram → API setup with Instagram login → Business login settings:**

| فیلد | مقدار |
|---|---|
| OAuth redirect URI | `https://igflow-xxxx.vercel.app/api/instagram/callback` |
| Deauthorize callback | `https://igflow-xxxx.vercel.app/api/instagram/deauthorize` |
| Data deletion request | `https://igflow-xxxx.vercel.app/api/instagram/data-deletion` |

**Webhooks:**

| فیلد | مقدار |
|---|---|
| Callback URL | `https://igflow-xxxx.vercel.app/api/webhooks/instagram` |
| Verify token | همان `IG_WEBHOOK_VERIFY_TOKEN` |

فیلدها: `comments` · `messages` · `messaging_postbacks`

> این بار دیگر هرگز لازم نیست این آدرس‌ها را عوض کنید.

## مرحلهٔ ۵ — بررسی سلامت

<div dir="ltr">

```bash
curl https://igflow-xxxx.vercel.app/api/health
```

</div>

باید ببینید:

<div dir="ltr">

```json
{"status":"ok","checks":{"database":"ok"}}
```

</div>

اگر `database` خطا داد، `DATABASE_URL` اشتباه است یا پورت ۵۴۳۲ را به‌جای ۶۵۴۳ گذاشته‌اید.

تست وب‌هوک:

<div dir="ltr">

```bash
curl "https://igflow-xxxx.vercel.app/api/webhooks/instagram?hub.mode=subscribe&hub.verify_token=YOUR_TOKEN&hub.challenge=test123"
```

</div>

باید دقیقاً `test123` برگردد.

**آزمون نهایی:** روی یکی از پست‌هایتان با یک حساب دیگر کامنت حاوی کلیدواژه بگذارید. باید ظرف چند ثانیه DM دریافت کنید. سپس در Vercel → Logs مسیر `/api/webhooks/instagram` را ببینید.

## نگهداری خودکار

فایل `vercel.json` یک cron روزانه (۰۳:۰۰ UTC) روی `/api/cron/maintenance` تعریف کرده که:

۱. **توکن‌های نزدیک به انقضا را تمدید می‌کند** — توکن بلندمدت اینستاگرام ۶۰ روز اعتبار دارد و بدون تمدید، اتصال کاربر بی‌صدا قطع می‌شود.
۲. **رویدادهای جامانده را دوباره پردازش می‌کند** — تور ایمنی برای وقتی که پردازش درون‌خطی ناتمام مانده باشد.

این مسیر با `CRON_SECRET` محافظت می‌شود؛ Vercel هدر مجوز را خودکار می‌فرستد.

## عیب‌یابی

<details>
<summary><strong>وصل می‌شود ولی هیچ DMای نمی‌آید</strong></summary>

۱. در Vercel → Logs ببینید آیا `/api/webhooks/instagram` اصلاً فراخوانی می‌شود؟
   - **نه** ⇒ مشکل از تنظیمات وب‌هوک در داشبورد متاست
   - **بله** ⇒ ادامه دهید
۲. مقدار `INLINE_WEBHOOK_PROCESSING` را چک کنید؛ اگر روی `false` است بردارید
۳. `/api/cron/maintenance` را دستی با هدر `Authorization: Bearer $CRON_SECRET` صدا بزنید و مقدار `stuckFound` را ببینید
</details>

<details>
<summary><strong>خطای «remaining connection slots reserved»</strong></summary>

از اتصال مستقیم (۵۴۳۲) استفاده کرده‌اید. به **Transaction pooler** روی پورت **۶۵۴۳** تغییر دهید و Redeploy کنید.
</details>

<details>
<summary><strong>دیپلوی با خطای cron شکست می‌خورد</strong></summary>

پیام: *«Hobby accounts are limited to daily Cron Jobs»*

یعنی زمان‌بندی بیش از روزی یک بار است. مقدار پیش‌فرض `vercel.json` (`0 3 * * *`) مجاز است؛ اگر تغییرش داده‌اید برگردانید.
</details>

<details>
<summary><strong>بعد از ورود، بلافاصله بیرون می‌افتم</strong></summary>

`AUTH_COOKIE_CROSS_SITE` باید روی production مقدار `false` داشته باشد. اگر `true` باشد کوکی `SameSite=None` می‌شود که برای دامنهٔ عادی لازم نیست.
</details>

<details>
<summary><strong>دیتابیس خالی است / جدول پیدا نمی‌شود</strong></summary>

migration در اولین اتصال اجرا می‌شود. یک بار `/api/health` را صدا بزنید و لاگ‌ها را ببینید. اگر خطای دسترسی بود، رمز داخل `DATABASE_URL` را بررسی کنید (کاراکترهای خاص باید URL-encode شوند).
</details>
