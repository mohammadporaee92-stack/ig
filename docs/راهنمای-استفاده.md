# راهنمای استفاده از IGFlow

این سند توضیح می‌دهد **چطور از برنامه استفاده کنید** — از ورود تا ساخت اولین اتوماسیون و دیدن نتیجه.

---

## قدم ۰ — اجرای برنامه

```bash
cd igflow
npm install        # نصب وابستگی‌ها  ← اول این
npm run setup      # ساخت .env.local + migrate + seed
npm run dev
```

> **ویندوز:** اگر خطای `'next' is not recognized` دیدید یعنی `npm install` اجرا نشده. اگر خطای `EALLOWSCRIPTS` گرفتید، تنظیم سراسری npm روی سیستم شماست نه مشکل پروژه — راه‌حل در بخش «ویندوز» فایل README آمده است.

آدرس: <http://localhost:3000>

```
ایمیل: demo@igflow.app
رمز:   demo12345
```

> اگر برنامه را داخل قاب پیش‌نمایش می‌بینید و ورود کار نکرد، آن را در **تب جداگانه** باز کنید. دلیلش در بخش عیب‌یابی README آمده است.

## نمای کلی: برنامه چه کار می‌کند

```
کاربر زیر پست شما کامنت می‌گذارد: «دوره»
        ↓
IGFlow کلیدواژه را تشخیص می‌دهد
        ↓
زیر کامنت پاسخ عمومی می‌دهد: «برات دایرکت کردم 📩»   (اختیاری)
        ↓
به او دایرکت خصوصی می‌فرستد + یک دکمه
        ↓
کاربر دکمه را می‌زند  ←← این مرحله حیاتی است
        ↓
حالا IGFlow می‌تواند بررسی کند فالو کرده یا نه
        ↓
فالو کرده؟  →  محتوای اصلی ارسال می‌شود ✅
فالو نکرده؟ →  پیام «اول فالو کن» + دکمهٔ «بررسی مجدد»
```

### چرا کاربر باید دکمه بزند؟

این مهم‌ترین نکته برای درک رفتار برنامه است.

اینستاگرام اجازه نمی‌دهد وضعیت فالو کسی را بدانید مگر اینکه او **با شما در دایرکت تعامل کرده باشد**. کامنت گذاشتن کافی نیست. تنها چیزهایی که این اجازه را می‌سازند: پیام دادن کاربر، یا زدن دکمه (Quick Reply / Icebreaker / منوی دائمی).

پس ترتیب کار این‌طور طراحی شده که اول کاربر را به دایرکت بیاوریم و یک دکمه جلویش بگذاریم. **بدون آن دکمه، بررسی فالو غیرممکن است.**

> این محدودیت خود Meta است، نه ضعف برنامه. هر ابزاری که ادعا کند بدون تعامل کاربر فالو را تشخیص می‌دهد، یا از روش غیررسمی استفاده می‌کند یا دروغ می‌گوید.

## قدم ۱ — اتصال حساب اینستاگرام

به صفحهٔ **«اینستاگرام»** بروید و دکمهٔ **«اتصال اینستاگرام»** را بزنید.

به صفحهٔ رسمی اینستاگرام منتقل می‌شوید، اجازه می‌دهید، و برمی‌گردید. همین.

**چیزی که لازم نیست:** صفحهٔ فیسبوک، Meta Business Suite، رمز اینستاگرام، کپی کردن توکن.

**چیزی که لازم است:** حساب شما باید **Professional** (Business یا Creator) و **عمومی** باشد.

> در حالت نمونه (seed) یک حساب آزمایشی `@demo_business` از قبل متصل است تا بتوانید محیط را ببینید بدون اینکه حساب واقعی وصل کنید.

## قدم ۲ — ساخت اتوماسیون (ویزارد ۷ مرحله‌ای)

به **«اتوماسیون‌ها» ← «ساخت اتوماسیون»** بروید.

### مرحله ۱ — نام

فقط برای خودتان است. مثلاً «دورهٔ رایگان ChatGPT».

### مرحله ۲ — تریگر

انتخاب کنید روی **همهٔ پست‌ها** اجرا شود یا فقط **پست‌های مشخص**.

### مرحله ۳ — کلیدواژه‌ها

کلماتی که وقتی در کامنت بیایند اتوماسیون فعال می‌شود.

| گزینه | معنی |
|---|---|
| **حاوی** (پیش‌فرض) | کامنت «سلام دوره رو میخوام» با کلیدواژهٔ «دوره» مطابقت دارد |
| **دقیق** | فقط کامنتی که **عیناً** «دوره» باشد |
| حساس به حروف بزرگ/کوچک | معمولاً خاموش بماند |
| **کلیدواژه‌های منفی** | اگر کامنت شامل این کلمات باشد، اجرا **نمی‌شود** |
| یک‌بار برای هر کاربر در هر پست | روشن بماند — جلوی اسپم را می‌گیرد |

> چند کلیدواژه بنویسید: `دوره، دوره رایگان، لینک، course`

### مرحله ۴ — Follow Gate

اگر می‌خواهید محتوا فقط به فالوورها برسد، این را روشن کنید.

| تنظیم | توضیح |
|---|---|
| **سقف بررسی مجدد** | چند بار به کاربر فرصت داده شود دوباره امتحان کند (پیش‌فرض ۳) |
| **سیاست وضعیت نامشخص** | وقتی نمی‌شود فالو را تشخیص داد چه کنیم |

سه حالت برای «نامشخص»:

- **ارسال کن** (پیش‌فرض) — سخت‌گیری نکن، محتوا را بفرست
- **مسدود کن** — تا وقتی مطمئن نشدی نفرست
- **خطا بده** — اجرا را ناموفق ثبت کن

> اگر مطمئن نیستید، همان «ارسال کن» را بگذارید. تجربهٔ کاربر بهتری دارد.

### مرحله ۵ — پیام‌ها

اینجا مهم‌ترین بخش است. چهار پیام دارید:

| پیام | کجا ظاهر می‌شود | نکته |
|---|---|---|
| **پاسخ عمومی** | زیر کامنت، برای همه قابل دیدن | اختیاری. مثلاً «دایرکتو چک کن 📩» |
| **پیام خصوصی** | اولین دایرکت | **حتماً یک دکمه بگذارید** — بدون آن ادامهٔ مسیر قفل می‌شود |
| **پیام Follow Gate** | وقتی کاربر فالو نکرده | یک دکمهٔ «بررسی مجدد» بگذارید |
| **محتوای اصلی** | جایزهٔ نهایی | لینک، فایل، هر چه وعده داده‌اید |

#### متغیرها

در متن پیام‌ها می‌توانید از این‌ها استفاده کنید:

| متغیر | جایگزین می‌شود با |
|---|---|
| `{{username}}` | نام کاربری کامنت‌گذار |
| `{{first_name}}` | نام کوچک او |
| `{{comment}}` | متن کامنتش |
| `{{keyword}}` | کلیدواژه‌ای که مطابقت داشت |
| `{{link}}` | لینکی که در همین مرحله وارد می‌کنید |

**فیلد «لینک شما»** پایین همین مرحله است. هر چه آنجا بگذارید، جای `{{link}}` می‌نشیند. اگر خالی بماند `{{link}}` به هیچ تبدیل می‌شود.

مثال پیام اصلی:

```
بفرما {{first_name}} 🎁
این هم لینک دوره:
{{link}}
```

#### محدودیت‌هایی که برنامه جلویشان را می‌گیرد

| مورد | حد مجاز |
|---|---|
| طول متن پیام | ۱۰۰۰ بایت |
| تعداد دکمه | ۱۳ |
| طول عنوان دکمه | ۲۰ کاراکتر |
| تصویر / ویدیو | ۸MB / ۲۵MB |

اگر از حد بگذرید، هنگام ذخیره پیام خطای فارسی می‌بینید.

> ⚠️ دکمه‌ها روی **نسخهٔ دسکتاپ اینستاگرام نمایش داده نمی‌شوند** — این محدودیت رسمی Meta است. کاربران موبایل مشکلی ندارند.

### مرحله ۶ — بازبینی

خلاصهٔ تنظیمات + **پیش‌نمایش بصری جریان**. اینجا ببینید مسیر همان چیزی است که می‌خواستید.

### مرحله ۷ — فعال‌سازی

**فعال** کنید تا شروع به کار کند، یا به‌صورت **پیش‌نویس** ذخیره کنید.

> اتوماسیون در حالت پیش‌نویس **هیچ کاری نمی‌کند**. اگر چیزی ارسال نشد، اول همین را بررسی کنید.

## قدم ۳ — دیدن نتیجه

| صفحه | چه چیزی نشان می‌دهد |
|---|---|
| **داشبورد** | آمار کلی، اجراهای اخیر |
| **اتوماسیون‌ها** | لیست، ویرایش، کپی، فعال/غیرفعال، حذف |
| **گزارش اجراها** | تک‌تک اجراها با وضعیت دقیق |
| **تحلیل‌ها** | نمودار عملکرد در طول زمان |

### معنی وضعیت‌ها

| وضعیت | یعنی |
|---|---|
| `completed` | کامل شد ✅ |
| `awaiting_user_interaction` | منتظریم کاربر دکمه را بزند — **این خطا نیست** |
| `follow_gate_sent` | پیام «اول فالو کن» رفته، منتظر بررسی مجدد |
| `skipped` | عمداً رد شد (تکراری بود یا کلیدواژهٔ منفی داشت) |
| `failed` | مشکلی پیش آمد — در صفحهٔ گزارش دلیلش نوشته شده |

> بیشتر اجراها در `awaiting_user_interaction` می‌مانند و این **طبیعی است**. یعنی کاربر دایرکت را گرفته ولی هنوز دکمه را نزده.

## مشکلات رایج

<details dir="rtl">
<summary><b>هیچ اتفاقی نمی‌افتد</b></summary>

به ترتیب بررسی کنید:

1. اتوماسیون **فعال** است یا هنوز پیش‌نویس؟
2. حساب اینستاگرام **متصل** است؟ (صفحهٔ تنظیمات ← اینستاگرام)
3. اگر `REDIS_URL` تنظیم کرده‌اید، آیا `npm run worker` اجراست؟ **بدون worker هیچ پیامی ارسال نمی‌شود و هیچ خطایی هم نمی‌بینید.**
4. وبهوک در داشبورد Meta ثبت و تأیید شده؟
5. کامنت از خود صاحب پیج بوده؟ آن‌ها عمداً نادیده گرفته می‌شوند تا حلقه ایجاد نشود.
</details>

<details dir="rtl">
<summary><b>دایرکت می‌رسد ولی محتوای اصلی نه</b></summary>

به احتمال زیاد کاربر **دکمه را نزده**. وضعیت اجرا را ببینید؛ اگر `awaiting_user_interaction` است، همه‌چیز درست کار می‌کند و فقط منتظر اوست.

مطمئن شوید پیام خصوصی‌تان **واقعاً یک دکمه دارد**. بدون دکمه، مسیر همان‌جا متوقف می‌ماند.
</details>

<details dir="rtl">
<summary><b>خطای «User consent is required»</b></summary>

طبیعی است. یعنی کاربر هنوز در دایرکت تعاملی نداشته. با زدن دکمه حل می‌شود.
</details>

<details dir="rtl">
<summary><b>خطای «outside of allowed window»</b></summary>

پنجرهٔ ۲۴ ساعته بسته شده. اینستاگرام اجازه نمی‌دهد بعد از ۲۴ ساعت از آخرین تعامل کاربر، به او پیام بدهید. راه دور زدن رسمی ندارد.
</details>

<details dir="rtl">
<summary><b>{{link}} در پیام خالی است</b></summary>

فیلد **«لینک شما»** در مرحلهٔ ۵ ویزارد را پر کنید.
</details>

## چند توصیهٔ عملی

- **کلیدواژه‌های متنوع بگذارید** — مردم «دوره»، «دوره رایگان»، «لینک» و «link» می‌نویسند.
- **پیام خصوصی را کوتاه نگه دارید** — هدفش فقط این است که کاربر دکمه را بزند.
- **متن دکمه باید واضح باشد** — «دریافت فایل 📥» بهتر از «ادامه» است.
- **Follow Gate را اجباری نکنید مگر لازم باشد** — اصطکاک اضافه می‌کند و بخشی از کاربران را از دست می‌دهید.
- **اول با پست کم‌بازدید تست کنید** — نه روی پستی که قرار است وایرال شود.
- **اعلام ربات بودن را روشن بگذارید** — سیاست Meta شفافیت را الزامی می‌کند و در برخی کشورها قانون است.

## مسیر رسیدن به کاربران واقعی

تا وقتی اپ Meta شما در حالت **Standard Access** است، فقط روی حساب‌هایی کار می‌کند که خودتان مالکشان هستید.

برای سرویس‌دهی به دیگران لازم است:

1. **Business Verification** — چند روز طول می‌کشد، زودتر شروع کنید
2. **App Review** برای سه مجوز `instagram_business_basic`، `instagram_business_manage_comments`، `instagram_business_manage_messages`

> در ویدیوی App Review حتماً **کل مسیر** را نشان دهید: کامنت گذاشتن، رسیدن دایرکت، زدن دکمه، دریافت محتوا. درخواست‌هایی که فقط اسکرین‌شات دارند رد می‌شوند.

جزئیات کامل استقرار: [`docs/13-deployment.md`](13-deployment.md)
